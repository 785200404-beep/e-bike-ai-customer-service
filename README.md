# 电动车店智能客服（首驱 · 南宁一网）

一个**从零搭到产品化**的电动车店客服 AI：LoRA 微调分流器"学徒"看门，DeepSeek 云端"老师傅"答题。能查真实产品价目表、算账、查库存、拒坑客户，还会把每次问答存下来反哺自己（数据飞轮）。

> 用到的核心技术：RAG 检索 · ReAct 工具调用 · LoRA 微调 · 模型路由 · 评估体系 · 数据飞轮 · 对齐守则

## 项目亮点

- **分层模型路由（省钱又稳）**：本地 Qwen3-0.6B + LoRA 分流器（**19MB 补丁，只训 0.84% 参数**）拦截违规/分流，只有正常问题才调用 DeepSeek 云端——简单活给学徒、难活给老师傅。
- **一套完整工具链**：RAG 查产品 + `CALC` 计算器算账 + `CHECK_STOCK` 查库存（没指定车型会自动反问"想了解哪款车的库存"）+ 守则防编造/拒坑。
- **评估先行的工程习惯**：客服 10 题 100%、库存 7 题 100%、10 题"绕弯子/口语"真实感压测全对、稳定性对比云端 3/3 一致。
- **数据飞轮跑通了一整圈**：真实压测暴露"翻新验车被误杀" → 补 14 条真实问法 → 重训 → 修复。实测案例，不是 PPT。

## 架构

```
客户提问
  │
  ▼
分流器学徒（Qwen3-0.6B + LoRA，本地 19MB）── 拒客违规 → 直接拦（免费）
  │ 正常问题
  ▼
老师傅（DeepSeek 云端）
  ├─ RAG 检索 → 价目表资料（首驱 6 款在售 + 5 款待公布 + 门店服务 + 售后）
  ├─ CALC 计算器 → 价格合计/折扣
  ├─ CHECK_STOCK 库存 → 指定车型查 / 没指定反问
  └─ 守则 → 不编造 · 拒坑 · 售后按三包
  │
  ▼
logs/chats.jsonl（每次问答一行 JSON = 数据飞轮原料）
```

## 快速开始

```bash

pip install torch transformers peft

# 2.（可选）复现分流器：造数据 → LoRA 训练 → 19MB 补丁
cd ft_shunt
python make_shunt_data.py    # 62 条训练 / 16 条测试
python train_ft.py           # loss 5.77 → 0.07，几分钟

# 3. 跑客服（老师傅走 DeepSeek 云端，分流器本地）
LLM=deepseek DEEPSEEK_API_KEY=sk-xxx MODEL_NAME=Qwen/Qwen3-0.6B python customer_service.py

# 纯本地兜底（断网也能跑）
MODEL_NAME=Qwen/Qwen3-1.7B python customer_service.py
```

## 关键决策 & 踩坑（面试能讲的干货）

1. **为什么要微调分流器而不是微调客服？** 客服 RAG 够用（先 Prompt → RAG → Agent → 微调 → 换大脑的决策树）；分流器"问题→固定类别"的新格式 Prompt 不可靠 + 小模型省钱 → 命中微调条件③④。
2. **LoRA 只训 0.84% 参数**（504 万 / 6 亿），补丁 19MB（原模型 1.2GB）；对比 0.6B vs 1.7B 同数据同超参都 100% → 任务太简单，**先小后大，数据说话**。
3. **敏感词会误杀**：训练数据里"翻新"只出现在违规样本 → 模型把"验翻新车"的正常客户也拦了。修复：往正常类补多条带"翻新"的问法，**敏感词要"两边都见"才学得会**。
4. **工具返回的措辞会带偏模型**：工具消息里写"请确认车型名"，模型当成"让自己反问客户"；改成"请直接告诉客户店里没有"，就老实了。
5. **评估脚本也会冤枉模型**：模型答 `12,248`（千分位逗号）被判错 → 判定前先去掉逗号。
6. **数字格式 / 检索 top_n / 模型随机性**都会骗人 → 评估要跑多次取平均。
7. **API key 安全**：全程走环境变量（`DEEPSEEK_API_KEY`），不落任何文件、不提交仓库。
